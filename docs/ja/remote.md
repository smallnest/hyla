# リモートマシン

セッションは別のマシンで動きながら、このウィンドウのサイドバーに居座れます。各マシンが自分の **hylad** を持つので、ノートを閉じてもその仕事は止まりません。

![サイドバーの SSH ホスト: 上はこのマシンのセッション、下は各マシンのセッション](./images/remote-hosts-ja.jpg)

*マシンごとにサイドバーにまとまりがあり、そこで動くセッションが並びます。*

## マシンを追加する

サイドバーの **+** メニューで **Add SSH Host…** を選ぶと、SSH ホスト、WSL ディストリビューション、もう一つの Hyla を追加できます。Pod なら **Add K8s Pod…** です。

| 種類          | アドレス                                          |
| ------------- | ------------------------------------------------- |
| SSH           | `me@devbox`、または `ssh://me@devbox:2222`        |
| WSL           | `wsl://Ubuntu`                                    |
| もう一つの Hyla | `tailcat://` とその[ペアコード](./remote.md#tailcat) |
| K8s Pod       | Pod の名前空間と名前                              |

そのマシンに Hyla が必要です。入っていない、あるいは手元より古いときは、接続越しにインストールや更新を申し出ます。同じホストは[設定ファイル](./configuration.md#hosts)にも `host = name=address` として書け、ホストごとに `color=` と ` remote-control` を付けられます。

## サイドバーで

各マシンのセッションは自分のものの隣に並び、動いているホストと与えた色が付きます。対応が必要なセッションは、どこで動いていても同じように目立ちます。ファイル、ペイン、[CLI](./cli.md) もこのマシンと同じです: そのマシンで `hyla` を動かせば、そこでセッションが始まります。

## つながりが切れたら

ノートが眠ったり回線が切れたりすると、ホストは未接続として表示され、セッションは失われません。**Reconnect Host** で戻り、**Disconnect Host** ならそのまま動かし続けます。ホストの `hylad` はアプリから再起動でき、ホストの Hyla が古ければその旨と更新がメニューに出ます。

ホストのプログラムがこのアプリを動かせるかは、許したときだけです: **設定 › リモート** にスイッチがあり、ホスト側の `remote-control` キーも同じ意味です。

## Tailcat

[Tailcat](https://github.com/smallnest/tailcat) はアカウントも Tailscale もなしに二台をつなぎます: 待ち受ける側が**ペアコード**を出し、もう一台に貼ると、リレーを通して互いを見つけます。見つかったあとは、ネットワークが許せばデータは二者の間を直接流れ、許さなければリレーを通ります。

Hyla は頼まれたときだけ待ち受けます: 設定ファイルの `listen = tailcat://:7473`、または **設定 › リモート** の待ち受けです。既定では切っています。
