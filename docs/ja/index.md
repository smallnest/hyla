# はじめに

Hyla は、コーディングエージェントと一緒に働くために作られた、macOS、Windows、Linux 向けのターミナルです。Claude Code、Codex、開発サーバー、テストウォッチャーを、それぞれ独立した**セッション**で動かします。Hyla はセッションをプロジェクトごとにサイドバーにまとめ、どれが作業中で、どれが対応待ちで、どれが完了したかを示します。

## ウインドウより長生きするセッション

セッションはアプリの中では動いていません。Hyla が代わりに起動する小さなデーモン **hylad** の中で動いています。Hyla を終了しても、すべては動き続けます。もう一度開けば、すべてのセッション、ペイン、スクロールバックが元のままです。

::: tip
Hyla を終了（<kbd>⌘</kbd> <kbd>Q</kbd>）しても、セッションは動き続けます。すべて終えるには、**Hyla › 終了してすべてのセッションを終える…**（<kbd>⌘</kbd> <kbd>⌥</kbd> <kbd>Q</kbd>）を使います。
:::

## エージェントのために

- **状態がひと目でわかる。** 各ペインは*作業中*、*待機中*、*アイドル*、*エラー*、*終了*のいずれかです。あなたを必要としているセッションは目立ち、<kbd>⌘</kbd> <kbd>J</kbd> でまっすぐそこへ移動できます。
- **大事なときに通知。** ほかの場所を見ている間にエージェントが完了したとき、失敗したとき、あなたの対応を待っているときに、Hyla が通知します。
- **エージェントが操作できる CLI。** `hyla` コマンドで、セッションの開始、ペインの分割、入力の送信、完了の待機、画面の読み取りができます。エージェントは自分の横で作業を動かし、自分の進捗を報告できます。
- **中身は Ghostty。** ターミナルの描画は libghostty なので、Ghostty のテーマ、フォント、設定キーが期待どおりに動きます。

## Kero からのアップグレード

Hyla は 2.1.37 まで **Kero** と呼ばれていました。その頃のアプリは Hyla に自動更新されないため、一度だけ Hyla をインストールしてください。初回起動時に設定とセッションが `~/.config/hyla`（macOS では `~/Library/Application Support/hyla`）へ移され、`KERO_*` 環境変数は `HYLA_*` として引き続き使えます。
